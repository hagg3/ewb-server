edenadmin

Connection

Pick or edit a profile, then test it. A local profile is a plain edenserver process on this Mac; a vps profile drives the server over ssh + systemd. No secrets are stored — ssh keys stay in ~/.ssh, the world password stays on the server.

Worlds

Hostable worlds under the profile's world_root. Download packs eden_world.model, the sign / spawn / player sidecars and the .gitignore as one tar. Upload and import both require the server to be stopped.

Upload a world bundle

Replaces the files in worlds/<name>/ with the contents of a previously downloaded tar. The server must be stopped.

Import a .eden world

Converts a saved .eden world into a hostable one. Project first to see the cell / REGION budget, then import. See docs/import.md.

Backups

World-file backups under the profile's backup_dir. A local profile flushes with edenctl save then copies the files here; a vps profile runs edenserverctl backup. Restore stops the server, swaps the files, and starts it again, keeping a -prerestore safety copy of the world it replaced.

Config

On a vps profile this reads and rewrites the systemd EnvironmentFile (/etc/edenserver.conf) through the validating edenserver-writeconf wrapper — never sudo tee. On a local profile it edits the managed flags in the profile's args. Review the diff, then Save. A restart drops every connected player.

Audit

    
The server's audit channel — every state-changing control command and
      every completed edit, with a UTC timestamp and the actor. Polled every 3 s.
      A dedicated --audit-file is the durable feed; without one this filters
      the [Audit] lines out of the live log (local) or journal
      (vps), which is reset by a restart.
